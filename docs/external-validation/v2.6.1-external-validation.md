## Validator protocol

Run on a machine with Docker, Git, Python 3.13+, and **no prior SoloLakehouse
development checkout**.

```bash
git clone https://github.com/Jiahong-Que-9527/SoloLakehouse.git
cd SoloLakehouse
git checkout <signed-post-v2.9-candidate>  # must include historical Block J baseline e534c73
cp .env.example .env
make setup
make verify
make demo
```

After `make demo` succeeds, confirm automatic lineage evidence (no manual
`make lineage-evidence`):

1. Open the Dagster UI (`http://localhost:3000`) and copy the latest successful
   `demo_data_flow_job` or `full_pipeline_job` run id.
2. List audit-bucket objects under `lineage/` for all five governed datasets
   (`fin.ecb_rates_bronze`, `fin.dax_daily_bronze`, `fin.ecb_rates_silver`,
   `fin.dax_daily_silver`, `fin.ecb_dax_features_gold`).
3. Confirm `make verify` reports Object Lock on `AUDIT_BUCKET`.

Optional manual fallback (should not be required on the happy path):

```bash
make lineage-evidence \
  DATASET_ID=fin.ecb_dax_features_gold \
  DAGSTER_RUN_ID=<run-id>
```

| Variable | How to obtain |

| `OPENMETADATA_TRINO_SERVICE_NAME` | Default `sololakehouse-trino` in `.env.example`; confirm the Trino service exists in OpenMetadata after first boot |
