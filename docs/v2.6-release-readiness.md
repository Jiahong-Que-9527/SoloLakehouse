# v2.6 Release Readiness

## Scope

v2.6 retains the protected v2.5 Compose/demo acceptance path and adds one
governance-evidence gate. It is not a claim of Object Lock/WORM enforcement,
automated catalog ingestion, production RBAC, token lifecycle management, or
regulatory compliance.

## Required evidence drill

Before a v2.6 tag, run the normal v2.5 checks and then demonstrate one complete
bundle for `fin.ecb_dax_features_gold`.

| Evidence source | Required proof |
|---|---|
| Contracts | `make validate-contracts` passes |
| OpenMetadata | The configured Trino service ingested `gold.ecb_dax_features`; the table has an owner; local-only token is configured |
| Iceberg | The table has a current snapshot and bucket-relative metadata location |
| Dagster | A successful run materialized `gold_features` |
| Audit output | The evidence command writes the canonical manifest under `lineage/` in `AUDIT_BUCKET` |

```bash
make lineage-evidence \
  DATASET_ID=fin.ecb_dax_features_gold \
  DAGSTER_RUN_ID=<successful-dagster-run-id>
```

The local deployment environment, never Git, must supply
`OPENMETADATA_TRINO_SERVICE_NAME` and `OPENMETADATA_AUTH_TOKEN`.

## Release record

Record the release commit, dataset ID, Dagster run ID, Iceberg snapshot ID,
audit object path, manifest `record_sha256`, and UTC timestamp. A missing
source, token, snapshot, materialization, or audit write is a failed gate: do
not emit or claim a partial evidence bundle.

## Known limitations

The manifest is a canonical, SHA-256-bound record in a stable audit layout. It
does not itself enforce immutable object retention. OpenMetadata ingestion is an
operator prerequisite, and the token is deliberately local-only. These limits
must remain visible in release notes until their respective controls are built.
