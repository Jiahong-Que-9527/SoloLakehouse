**Goal:** Serve the G01 energy observations from BigQuery over an authenticated FastAPI service on Cloud Run, with denied-by-default access and hard query guards.

**Architecture:** Ports-and-adapters like G01 — the core package defines a `QueryPort` and pure validation/guard logic tested against a fake; a lazy-import BigQuery adapter implements the port; FastAPI exposes the HTTP contract; Terraform creates the `energy_api` dataset, an authorized view over `energy.metric_observation`, distinct runtime/caller identities and one Cloud Run Service (min instances 0). Tests never touch the cloud.

**Tech Stack:** Python 3.12, uv + hatchling, FastAPI + uvicorn, google-cloud-bigquery (lazy), Terraform (GCS remote state), GitHub Actions + Workload Identity Federation, Cloud Run Service.

**Spec:** `gcp/02-energy-analytics-api/docs/design.md` · `gcp/02-energy-analytics-api/docs/implementation.md` · `gcp/02-energy-analytics-api/README.md`

## Global Constraints

- Region `europe-west3`; BigQuery dataset location `EUROPE-WEST3` (not `EU`).
- Preserve MWh from G01; `unit` is always `MWh` for `actual_load_mwh`.
- Every BigQuery query is parameterised; no string-concatenated SQL anywhere.
- Not public: Cloud Run invoker IAM is the v1 gate; no `--no-auth`/unauthenticated invocations.
- Guard values (design §4): span ≤ 31 days, statement timeout 15 s, maximum bytes billed 1 GB; guard violations are rejected **before** the query runs, or fail closed.
- min instances = 0 (scale to zero).
- Windows are half-open `[from, to)`; `from < to` required.
- One error shape everywhere: `{"code", "message", "request_id"}`.
- The runtime identity gets `dataViewer` on the **view only** — never on raw G01 tables; `jobUser` on the project.
- Costs: everything must stay inside free tier / trial credits (repo AGENTS.md cost gate). Expected SKUs: Cloud Run (request-based, scale-to-zero), BigQuery storage/queries on tiny data, Artifact Registry storage. Any plan output showing an unexpected billable SKU stops the delivery for owner approval.
- Local checks run via `uv`; no sudo; WSL commands go through script files in `~/.local/opt/` (PowerShell mangles inline quotes/pipes).
- Git identity per-command: `-c user.name=Jiahong-Que -c user.email=jiahongque25@gmail.com`; commit messages via `-F <file>`.

## Review Focus

1. **Half-open window boundary** — a query whose `to` equals an interval's `interval_start` must **include** that interval (`to` is exclusive, so `interval_start < to`). Wrong inclusive-`to` bugs hide here.
2. **Latest-release resolution** — with two releases present, a request without `release_id` must return rows from the **latest passed release only**, never mixing releases in one response.
3. **Guard ordering** — a 32-day request with an unknown metric: span check (400 `query_rejected`) must win deterministically over the 404; validation happens before any release lookup or query.
4. **Denial direction** — the runtime identity reads the view (200) and is denied the raw table (403). A mis-granted `dataViewer` on the `energy` dataset would silently pass every API test; the denial check is the only thing that catches it.
5. **Platform vs app errors** — a missing invoker returns Cloud Run's 403 **before** the app; the app's 400/404 shapes must never be produced by the platform path, and vice versa.
