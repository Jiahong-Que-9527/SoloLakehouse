## Implementation sequence

1. **Lock dbt & SQLFluff dependencies:** Add `dbt-core`, `dbt-duckdb`, and `sqlfluff` (+ templater) to `pyproject.toml` and regenerate `uv.lock`. Configure `.sqlfluff` with consistent casing, aliasing, and indentation rules.
2. **Configure dbt project & sources:** Create `dbt_project.yml`, `profiles.yml` (pointing to local DuckDB generated by E01), and `models/staging/sources.yml` with `loaded_at_field: _ingested_at` and freshness SLAs.
3. **Implement `staging` and `intermediate`:** Deduplicate `charging_sessions` to latest `event_seq`, cast monetary amounts to `DECIMAL(12,2)`, normalize timestamps to UTC/Berlin calendar dates, and join ECB FX (`<= revenue_date`) + SMARD wholesale EUR/MWh rates.
4. **Implement `marts` star schema:** Build `dim_stations`, `dim_tariffs`, `dim_date`, `fct_charging_sessions`, and `fct_daily_revenue` with explicit grain descriptions in `schema.yml`.
5. **CI & test harness:** Add `tests/test_dbt_models.py` (runs ingest + `dbt source freshness` + `dbt build --target duckdb` + fan-out assertion) and `.github/workflows/data-engineering.yml`; record acceptance evidence.

## Verification commands and negative drills

```bash
cd Data-engineering/reference-warehouse
uv run --locked ruff check .
uv run --locked pytest -v
uv run --locked sqlfluff lint dbt_project/models
uv run --locked dbt source freshness --project-dir dbt_project --profiles-dir dbt_project --target duckdb
uv run --locked dbt build --project-dir dbt_project --profiles-dir dbt_project --target duckdb
```

**Negative drill:** Inject an unaliased/misformatted SQL clause or stale `_ingested_at` timestamp (> 48h old) in a disposable DuckDB fixture and verify `sqlfluff lint` or `dbt source freshness` exits non-zero.
